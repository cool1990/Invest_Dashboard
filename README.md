## 宏观板块

页面分三层，每层只放别的层没有的东西：

1. **结论**：整体环境先写名字和它的意思（增长 × 通胀定象限：过热 / 通胀粘性 / 滞胀风险 / 稳健扩张 / 金发姑娘 / 放缓 / 复苏 / 低通胀 / 衰退风险），下面四行白话分别写经济、流动性、财政、货币，不带数字。再下面五个维度一行一个：标签 + 理由，每条理由是一个小结论加上用哪几个数、对照什么锚点得出的；标签不在理由里重复。模型预测（GDPNow、Nowcast）不进顶部总结。整体环境下面是判断变化日志，默认折叠，展开后每条写日期、因为哪条数据（北京时间和实际值）、哪一块从什么变成什么、当时的理由。
2. **依据**：五个维度各一块，只列决定那句话的几个数，每个数三列：最新值、较上期、对照的锚点（锚点文字和阈值都来自 `interpret.py`）。非农这类规则用 3 个月均值的，格子里直接写 3 个月均值，单月放备注。标「预测」的是模型预测，不进判断。下面是这几个数对应的图，其余收在「更多图表」里；通胀一块另附克利夫兰联储 Nowcast 与实际的对照。
3. **时间**：第一屏右边先是「今日发布」（按访问时的北京日期挑，写时间、指标、预测、前值，没有就写「无」），再是「即将发布」。每条带 1–5 星的重要程度，点「为什么」展开理由（时效是领先 / 同步 / 滞后、对美联储的分量）；进了规则的指标在理由最后附一行对本站标签的门槛。星级规则在 `pipeline/macro/importance.py`：看对美联储决策的分量、新信息量（当月第一个同类读数高，能被之前数据推算出来或只是修订的低）和时效，没列的条目不打星。「最近发布」（实际 vs 预期）在有数据之后才出现。

**判断方法**：每个维度按经济锚点判断，而不是和历史平均比。早期版本用过「2000 年以来的 z 分数、等权汇总」，已经去掉：和历史平均比没有经济含义（2000 年以来利率长期接近零，接近中性的利率也会被算成偏紧），等权汇总又会把分歧互相抵消。现在：

| 维度 | 怎么判断 |
|---|---|
| 增长 | 产出（上季核心 GDP，即对私人国内购买者的最终销售 = 消费 + 固定投资，按公布精度一位小数，对约 2% 潜在增速；GDP 总量分档不同时，句子里写明被净出口、库存或政府中哪一项拉低或拉高）与就业（非农 3 个月均值、失业率 12 个月变化、Sahm）分开判断；两者不一致时标「分化」。GDPNow 是模型预测，只作参考，没有实际值时才顶上。实际 PCE 3 个月年化和核心资本品订单列在依据里作参考，不进判断 |
| 通胀 | 水平（核心 PCE 同比对 2%）× 短期动能（3 个月年化与同比相差 ±0.3 个百分点），并看超级核心与 5y5y。克利夫兰 Nowcast 是模型预测，不改状态，也不进顶部总结；只有比最新官方值高或低超过 0.3 个百分点，才在通胀的理由里写「模型预计回升 / 回落」 |
| 流动性 | 资金市场（SOFR − IORB、准备金占 GDP，充足下限估计约 9–11%）、金融条件（NFCI）、信用（高收益利差）三块分开 |
| 财政 | 财政脉冲（赤字率 12 个月变化，收窄即拖累增长）与偿债压力（利息占 GDP、债务占 GDP）分开 |
| 货币 | 当前立场（实际政策利率对 0.5–1% 中性）与市场路径（到明年底隐含的加降息次数、与点阵图的差距）分开 |

规则和阈值都在 `pipeline/macro/interpret.py`，结果可复现。只用已经公布的数据定状态，模型预测只作参考。

**新数据怎么影响判断**（`pipeline/macro/scenario.py`）：
- 发布前：对进了规则的指标（非农、失业率、核心 PCE 环比、实际 GDP），把候选新值逐个加到序列末尾，用和页面相同的规则重算维度状态和整体环境，把结果相同的候选值并成一段，再压成一行写在「即将发布」该行下面：预期落在哪一段、哪个标签会变，只留预期两侧最近的门槛。变不了的写「仍为…」。只列页面上真有的标签（环比本身没有标签）；核心 CPI 不进任何标签，不写；已经公布过的期间（例如 GDP 终值）只是修订，只留时间和预期。
- 发布后：「最近发布」里对每条数据去掉这一期、加上这一期各算一次，写出判断有没有变、怎么变；附发布当天 2 年期国债的变化和年底 EFFR 隐含值在发布前后的变化。
- 判断变化日志：每次运行比较五个维度和整体环境的状态标签，有变化就追加到 `data/macro/state_log.csv`，并记下前 3 天的相关发布。只比较标签不比较句子，因为句子里的数字几乎每天都变。

**预期值**：
- 市场一致预期：每天读 ForexFactory 公开的本周、下周日历 JSON（非官方接口，免费），只留美国高、中影响条目，累积到 `data/macro/consensus.csv`。发布前多次看到同一条目时取最后一次的预期。实际值取 FRED 当前值（可能已修订），按参考期（例如 10 月初公布的非农对应 9 月）对齐。需要手工补录时写 `data/macro/consensus_manual.csv`，列相同。
- 模型预测：GDPNow（对比实际 GDP）、克利夫兰联储通胀 Nowcast（CPI、核心 CPI、PCE、核心 PCE 同比），存 `data/macro/nowcast.csv`。
- 这两类来源从本站上线后才开始累积，历史意外要等数据发布几次后才有。

| 维度 | 看什么 |
|---|---|
| 增长 | 实际 GDP（季环比年化、同比、年度）、核心 GDP、GDP 分项贡献（消费、固定投资、库存、政府、净出口）、GDPNow、非农、失业率、U-6、Sahm 规则、职位空缺与空缺/失业比、离职率、时薪、初请与续请、零售销售与控制组、实际 PCE、储蓄率、消费者信贷、信用卡拖欠率、耐用品与核心资本品订单、地区联储制造业调查、新屋开工/许可/销售/库存、房价、房贷利率 |
| 通胀 | PCE 与核心 PCE（同比、环比、3/6 个月年化）、PCE 按贡献拆分（食品、能源、核心商品、住房、核心服务除住房）、CPI 与核心 CPI、5y5y、10 年盈亏平衡、密歇根一年期预期 |
| 流动性 | 美联储负债结构与准备金拆分（总资产 − ON RRP − TGA − 流通中货币 − 其他）、准备金 4 周变化的来源、SOFR − IORB、EFFR − IORB、NFCI、高收益利差、美元指数 |
| 财政 | 滚动 12 个月赤字、赤字率、财年赤字率、利息支出占 GDP、债务占 GDP |
| 货币 | EFFR 路径（市场隐含 vs 点阵图）、EFFR 与目标区间、2 年期国债、实际政策利率、2Y − EFFR、10Y−2Y 与 10Y−3M、10 年名义与实际利率 |

**PCE 与核心 PCE 按贡献拆分**：某项贡献 ≈ 基期（环比用上月、同比用 12 个月前）的名义支出份额 × 该项价格变化。整体 PCE 拆成食品 / 能源 / 核心商品 / 住房 / 超级核心；核心 PCE 拆成核心商品 / 住房 / 超级核心（服务除能源、住房）。FRED 没有月度住房支出、月度汽油支出和月度核心商品价格，所以：住房名义 = 核心 × 上一年住房占核心的比重（年度）；核心商品名义 = 商品 − 食品 − 能源 × 能源商品占能源的比重（最近一季）；超级核心名义 = 核心 − 核心商品 − 住房。价格用核心 PCE、核心除住房（IA001176M）、超级核心（IA001260M）三条月度指数，住房和核心商品的贡献由差额得到。链式加总不严格可加，误差一般在 0.01 个百分点量级。

**ISM PMI** 不在 FRED，暂时用费城联储和纽约联储的制造业调查代替。

## 半导体与 AI 板块

目标：回答**半导体整体处在周期的哪个阶段**，用供给和需求说明理由，再分环节看景气集中在哪。做法和宏观页一样：按经济锚点判断、不用 z 分数，阈值都在 `pipeline/semis/interpret.py`。

第一屏从上到下：

1. **结论**：半导体整体处于上行、下行还是震荡，以及早期、中期还是后期，附一句含义和周期刻度（上行早 / 中 / 后 → 下行早 / 中 / 后，震荡另标）。
2. **为什么：供需五个维度**。需求端：AI 算力、传统终端；供给端：产能、库存、价格。每行写标签、投给哪个阶段和理由，最后写票数合计。
3. **分环节**：存储、AI 芯片与先进代工、成熟制程与手机、模拟与 MCU、半导体设备，每个环节一个状态（上行加速 / 上行放缓 / 触底回升 / 下行）和关键数。不进整体判断，用来看景气集中在哪、哪里先转弱。
4. **后续关注**：最能改变位置判断的几个指标，每项写当前值和转向信号（上行时写出现什么说明见顶，下行时写出现什么说明见底）。

下面是**指标详解**，按需求端、供给端、分环节排：每个数写最新值、较上期、锚点，下面一段话说明它判断什么、怎么判断、为什么有效（`pipeline/semis/build.py` 的 `ABOUT`），再往下是图。

**怎么定位置**（`interpret.position`）：
- 方向：AI 算力与传统终端两个需求档位取平均，≥ 0.5 为上行，≤ −0.5 为下行，其余为震荡；两个需求方向相反时注明「需求内部分化」。
- 阶段：五个维度按经典半导体周期各投一票，票最多的阶段胜出，平票取中期。

| 维度（上行时） | 投早期 | 投中期 | 投后期 |
|---|---|---|---|
| AI 算力 / 传统终端 | 增速从低位加速（AI 资本开支同比 < 30%，传统 < 5%） | 其余 | 增速从高位回落（AI > 40%、传统 > 15% 且比上季下降），或需求放缓 |
| 库存 | 被动去库、主动去库 | 主动补库 | 被动补库 |
| 价格 | 企稳且 PPI 同比 ≤ 10%，或 PPI < 5% 时涨价 | 涨价 | 企稳但 PPI 同比 > 10%（高位涨不动） |
| 产能 | 收缩 | 平稳 | 扩张 |

下行时反过来：需求刚放缓、被动补库、价格高位刚停涨、产能仍在扩，投下行早期；需求降幅收窄、去库接近尾声（出货 − 库存转正）、跌价收窄到企稳、产能收缩，投下行后期。

**各维度的标签**（每个数按锚点投 +1 / 0 / −1，取平均，≥ 0.5 为强档，≤ −0.5 为弱档）：

| 维度 | 标签 | 进判断的数（锚点） |
|---|---|---|
| 需求端 · AI 算力 | 加速 / 扩张 / 放缓 / 收缩 | 5 家云厂商资本开支合计同比（> 20% 扩张、< 0 收缩，比上季抬升 ≥ 5 个百分点为加速）；OpenRouter 最近 30 天用量较前 30 天（> 20% / < 0）；英伟达、台积电、博通下财年 EPS 30 天修正（±2%） |
| 需求端 · 传统终端 | 同上 | 美国计算机与电子产品新订单 3 个月同比（> 5% / < 0）；联发科 + 联电近 3 个月营收同比（> 10% / < 0）；德州仪器、微芯、亚德诺单季营收同比（> 5% / < 0）；高通、英特尔 EPS 修正 |
| 供给端 · 产能 | 扩张 / 平稳 / 收缩 | 应用材料、泛林、科磊营收同比（> 10% / < 0）；ASML 订单出货比（> 1.1 / < 0.9，手工录入）；美国半导体产能利用率、工业产出、台积电资本开支指引作参考 |
| 供给端 · 库存 | 主动去库 / 被动去库 / 主动补库 / 被动补库 | 出货同比 × 库存同比定阶段；出货 − 库存 > 0 库存压力在减轻。首选韩国统计局半导体出货、库存指数，没有 key 时用美国计算机与电子产品（A34SVS、A34STI）；公司库存天数作参考 |
| 供给端 · 价格 | 涨价 / 企稳 / 跌价 | DRAM 现货 30 天 ±5%（历史不足 30 天时 7 天 ±2%）；现货比合约高 > 5% 时下季合约价大概率跟涨（合约价手工录入）；PPI 同比、NAND、GPU 租金作参考 |

**分环节**（`interpret.segment_state`：主指标同比 ≥ 0 且比上期抬升为上行加速，≥ 0 但回落为上行放缓，< 0 但跌幅收窄为触底回升，< 0 且继续回落为下行）：

## 数据

- 来源：圣路易斯联储 [FRED](https://fred.stlouisfed.org/) 的公开 CSV，不需要 API key。序列清单在 `pipeline/macro/indicators.py`。
- 全历史下载，原样存在 `data/raw/fred/<ID>.csv`（列 `date,value`，数值和单位与 FRED 一致）。图表默认显示近 5 年，可切 2 年 / 10 年 / 全部（图表数据从 1990 年起，日频压成周频）。
- 市场隐含 EFFR（下月 / 年底 / 明年底）来自每天早晨的笔记。旧站已把它整理进 `data/sentiment/series.csv`，本仓库从那份公开文件里只挑这三行，累积到 `data/macro/effr_expectations.csv`。
- `data/macro/dashboard.json`：页面读的唯一文件。
- `data/macro/status.json`：每条序列这次有没有下载成功、最新观测日期。下载失败的序列沿用上次的文件，页面底部「数据状态」会列出来。

## 自动更新

- `.github/workflows/update-macro.yml`：每天 22:40 UTC（北京时间 06:40）跑测试、下载、生成；数据有变化就提交并发布网页。也可以在 Actions 页面手动运行。
- `.github/workflows/update-semis.yml`：每天 02:10 UTC（北京时间 10:10，旧站早晨笔记之后）；每月 5–12 日 08:10 UTC 再跑一次接台湾月营收。可选 Secret `KOSIS_API_KEY`。两个更新工作流推送前都先 `git pull --rebase`，写的文件不重叠。
- `.github/workflows/pages.yml`：改网页或合并到 `main` 时发布。

首次使用需要在仓库 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。

## 本地运行

只用 Python 3.12 标准库。

```bash
python3 scripts/update_macro.py            # 下载并生成（需要能访问 FRED）
python3 scripts/update_macro.py --offline  # 只用已下载的 CSV 重新生成
python3 scripts/update_semis.py            # 半导体：下载并生成（需要能访问旧站、FRED、证交所、SEC）
python3 scripts/update_semis.py --offline
python3 -m unittest discover -s tests
python3 scripts/build_site.py && python3 -m http.server 8000 -d dist
```

浏览器打开 http://localhost:8000/ 。页面用 `fetch` 读数据，不能直接双击 html 打开。
